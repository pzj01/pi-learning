# Pi Learning

一个用于系统学习 **AI Agent 开发原理**、理解 [Pi](https://github.com/badlogic/pi-mono) 的实践型学习仓库。

这个仓库不仅用于保存学习笔记，也用于通过编写代码、阅读源码和小型实验，逐步建立对 Agent 系统的整体理解。

## 学习目标

本项目希望逐步达成以下目标：

- 理解 AI Agent 的基本工作机制，而不只是会调用现成框架。
- 使用 TypeScript 从零实现一个最小可运行的 Agent。
- 通过阅读 Pi 的源码，理解成熟 Agent 项目的架构与设计取舍。
- 将理论、源码阅读与动手实验结合起来。
- 最终具备独立设计、实现、调试和维护 Agent 应用的能力。

## 学习方法

本项目采用“**先实现最小版本，再对照成熟项目，最后独立实践**”的路线：

1. **自己实现**：先在 `mini-agent/` 中实现模型调用、工具调用和 Agent 执行循环，建立直观认识。
2. **理解 Pi**：沿着一次请求的执行路径阅读源码，观察 Pi 如何组织相同或更复杂的能力。
3. **记录差异**：把自己的实现与 Pi 的设计进行比较，弄清差异解决了什么问题，以及是否值得借鉴。
4. **小型实验**：在 `labs/` 中隔离验证新机制，避免为了实验而不断扩大核心项目。
5. **沉淀知识**：把经过理解和验证的结论整理到 `notes/`，并通过 `ROADMAP.md` 维护总体进度。

学习过程中不追求一次性复刻整个 Pi。优先理解关键机制，再根据实际问题逐步深入。

## 目录说明

```text
pi-learning/
├── README.md             # 项目介绍、学习目标和目录导航
├── ROADMAP.md            # 学习阶段、当前进度和下一步计划
├── mini-agent/           # 自己编写的最小 Agent 项目
├── notes/                # 概念笔记、源码分析和实现对比
├── labs/                 # 独立的小型实验与验证代码
└── teach/                # Teach Skill 使用的课程与学习记录
    ├── MISSION.md        # 学习使命与目标
    ├── RESOURCES.md      # 学习资料清单
    ├── lessons/          # 课程材料
    └── learning-records/ # 学习过程与掌握情况记录
```

各目录的职责如下：

- **`mini-agent/`**：保留最小 Agent 的核心实现。除非实验确实需要，不要把所有探索性代码都塞进这里。
- **`notes/`**：记录概念解释、源码阅读结果、关键问题和设计取舍。优先用自己的话总结，而不是复制大量原文。
- **`labs/`**：验证单一技术点，例如事件流、上下文压缩或工具执行策略。实验成熟后，再决定是否整合进 `mini-agent/` 或独立项目。
- **`teach/`**：由 Teach Skill 协助组织课程、练习和学习记录。它是学习工作区，不取代整个仓库的总体路线图。
- **`ROADMAP.md`**：维护全局学习方向与阶段状态。具体课程安排可以由 Teach Skill 协助细化。

## 学习原则

1. **先理解，再扩展**：每次优先解决一个明确问题，避免过早设计复杂架构。
2. **以可运行代码验证理解**：能复述概念不等于掌握，尽量通过小实验验证。
3. **区分事实与推断**：阅读源码时记录文件位置、调用关系和观察到的行为；对设计动机的判断要标明是推断。
4. **记录问题和结论**：每次学习尽量留下一个可复用的结论、代码成果或待解决问题。
5. **控制学习范围**：按需深入，不以通读所有源码或复刻全部功能为目标。
6. **保护原有项目**：实验前确认 Git 状态；不要让课程生成或实验代码无意覆盖 `mini-agent/` 中已有的工作。

## 如何开始

1. 查看 [`ROADMAP.md`](./ROADMAP.md)，确认当前阶段与下一步任务。
2. 检查 `mini-agent/` 当前实现，确认已完成的能力和仍存在的缺口。
3. 选择一个具体学习问题，先通过代码或源码定位问题。
4. 在 `notes/` 或 `labs/` 中记录结论与验证结果。
5. 完成阶段目标后，更新 `ROADMAP.md`。

## 阶段完成标准

不要仅以“读完文档”作为完成标准。一个阶段原则上应至少留下：

- **解释**：能用自己的话说明核心机制。
- **实现或验证**：有可运行的代码、测试或明确的源码追踪结果。
- **复盘**：能说明方案的限制、关键取舍，以及下一步还需要理解什么。

## 范围说明

本仓库当前以学习和实验为主。它不要求一开始就成为生产级 Agent 框架，也不要求每个实验最终都合并到核心实现中。设计和目录可以随着学习进展逐步调整。
