Tool Call 消息协议

OpenAI 兼容 API 里，一次工具调用的消息结构与字段。课程会回看很少，这份速查表才是你会反复翻的东西。
字段形状依据本机 openai@7.32.0 的 resources/chat/completions.d.ts 核对。

骨架：两次请求，四条消息

  1. user
  2. → 请求 1
  3. assistant(tool_calls)
  4. 本地执行
  5. tool
  6. → 请求 2
  7. assistant(content)
第二次请求的 messages 数组（顺序即真相）
[
  { role: 'user',      content: '请计算 5 + 3' },                    // ① 你的问题
  { role: 'assistant', content: null,                                // ② 模型原样的回复
    tool_calls: [{ id: 'call_abc', type: 'function',
                   function: { name: 'calculator',
                               arguments: '{"operation":"add","a":5,"b":3}' } }] },
  { role: 'tool',      tool_call_id: 'call_abc',                      // ③ 你执行的结果
    content: '8' },
]

字段速查

消息必填说明
user content 字符串。多模态时可为内容块数组。
assistant
（模型产出）		 tool_calls[] 决定调工具时 content 常为 null，意图全在 tool_calls 里。
assistant
（你回填历史）		 role 把模型返回的整个 message 对象原样 push 进历史即可，别自己拼。
tool tool_call_id
content		 content 必须是字符串（string | 文本块数组），数字要先 String()。错误信息也作为 content 回传，这是让模型自我修正的常规做法。

tool_calls 元素的形状

ChatCompletionMessageFunctionToolCall
{
  id: string                        // 唯一 ID，回传结果时用它配对
  type: 'function'                // 联合类型的判别字段，用它收窄
  function: {
    name: string                  // 工具名，对应你 schema 里的 name
    arguments: string             // ⚠️ JSON 文本，不是对象，要 JSON.parse
  }
}

最小骨架

TypeScript · 一次完整往返（无循环）
const messages: ChatCompletionMessageParam[] = [
  { role: 'user', content: question },
]

for (let i = 0; i < MAX_STEPS; i++) {
  const res = await openai.chat.completions.create({ model, messages, tools })
  const msg = res.choices[0].message
  messages.push(msg)                                   // 先入历史，顺序不能乱

  if (!msg.tool_calls?.length) { console.log(msg.content); break }  // 停止条件

  for (const call of msg.tool_calls) {
    if (call.type !== 'function') continue
    const args = JSON.parse(call.function.arguments)
    messages.push({ role: 'tool', tool_call_id: call.id, content: dispatch(call.function.name, args) })
  }
}

上面这个骨架是最简形态（没有上界、没有错误兜底）。带刹车和兜底的完整版本见 速查 · Agent Loop 骨架；dispatch 是"按工具名分派执行"的占位，现在是那个 switch。

报错 → 病因对照

措辞随版本变化，看含义就行：

报错的大意真正的原因
role 为 tool 的消息必须是对前面 tool_calls 的回应 忘了把模型的 assistant 消息 push 进历史（实验 A）
assistant 的 tool_calls 后面的 tool 消息数量/ID 对不上 漏回了某次调用，或 tool_call_id 写错（实验 B）
TS2339: Property 'function' does not exist 没收窄联合类型，缺 if (call.type !== 'function') continue
Unexpected token / JSON.parse 抛异常 把 arguments 当成对象用了，或模型生成了非法 JSON
模型不调工具，直接编了个答案 工具 description 没写清"什么时候该用我"
reasoning_content must be passed back（仅 thinking 模式） 重放历史时手工挑了字段重建 assistant 消息，把 reasoning_content 丢了。必须 push 整个 message 对象，空字符串也不能省
不能把 tool call 消息插入对话中途 Chat Completions API 的限制，只能追加（push）。要插入得换 Anthropic /messages 或 Responses API
一句话原理

模型无状态、不执行。它只会：读取你发的完整历史 → 输出下一条消息。所谓 "agent loop"，就是"把它的输出追加进历史、干它要求你干的活、再问一次"的循环。
