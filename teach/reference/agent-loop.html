Agent Loop 骨架

工具调用协议见 上一份速查表；这份讲循环本身：怎么停、出错往哪去、每一步为什么要这么写。
字段形状依据本机 openai@7.32.0；finish_reason 取值依据 DeepSeek 官方 API 文档。

骨架（带刹车与兜底）

TypeScript · run() 的完整形态
const messages: ChatCompletionMessageParam[] = [{ role: 'user', content: userMessage }]

for (let step = 1; step <= MAX_STEPS; step++) {          // ① 上界：兜底刹车
  const res = await openai.chat.completions.create({ model, messages, tools })
  const msg = res.choices[0].message
  messages.push(msg)                                     // ② 整个对象入历史，顺序不能乱

  const calls = msg.tool_calls ?? []
  if (calls.length === 0) return msg.content ?? ''       // ③ 判据建在你能穷举的集合上

  for (const call of calls) {
    if (call.type !== 'function') {                        // ④ 联合类型收窄
      messages.push({ role: 'tool', tool_call_id: call.id, content: '不支持的类型' })
      continue
    }
    const content = await executeSafely(call.function.name, call.function.arguments)
    messages.push({ role: 'tool', tool_call_id: call.id, content })   // ⑤ 每个 id 恰好回一条
  }
}
// ⑥ 走到这里 = 撞上 MAX_STEPS，要大声报告，不要静默退出

三条不变式

#不变式违反的后果
② assistant 消息整个对象 push 进历史，不要手工挑字段重建 thinking 模式下丢掉 reasoning_content → 之后每一次请求都 400
⑤ 进入历史的每一个 tool_call.id，在下一次请求前都收到恰好一条 tool 消息 下一次请求 400，且报错信息不指向病因——病灶在上一轮的循环里
① 循环必须有独立于所有业务判断的上界 模型「每步都合规但一直在绕圈」时无限跑，烧的是你的 API 额度

停止判据：为什么不用 finish_reason === 'stop'

官方文档给出的取值集合是 6 个：

取值官方释义该停吗
'stop'命中自然停止点或你给的 stop 序列停
'tool_calls'模型调用了工具继续
'length'达到请求里指定的 max_tokens 上限停（并按失败处理）
'content_filter'内容因内容过滤器被省略停
'insufficient_system_resource'因推理系统资源不足，请求被中断停
'aborted'生成过程被中断停
本地 SDK 的类型和它对不上

openai@7.32.0 里 finish_reason 声明为 'stop' | 'length' | 'tool_calls' | 'content_filter' | 'function_call'——多了一个 DeepSeek 没有的 'function_call'，少了 'insufficient_system_resource' 和 'aborted'。所以你写 finishReason === 'aborted' 会直接报 TS2367（no overlap）。

结论：对第三方 API 返回的枚举值，按运行时实际返回处理，不要按类型声明处理。

判据建在你能穷举的集合上

不要问「finish_reason 是不是我认识的那几个值之一」（白名单，取值域在别人手里）；要问「模型这一轮有没有要求我干活」（tool_calls 有 / 没有，只有两种，在你手里）。

这样遇到任何意外取值，你默认停下——最坏的结果是少跑一轮，而不是烧一整晚额度。

错误去向决策表

唯一的判据：这个错误，模型能不能自己修正？

来源例子去向
模型的错 工具名不存在、参数类型不对、缺必填字段、arguments 不是合法 JSON 作为 tool 消息的 content 回传
工具的业务错 订单不存在、除数为 0、文件格式不对 同上（除非你刻意要区分）
环境的错 网络断、API key 失效、磁盘满、数据库连不上 向上抛，终止运行。回传只会让模型徒劳重试
达到 MAX_STEPS 模型合规地绕圈，或被截断后空转 console.warn 明确报告。不要静默 break
一句话

「跳过」不是错误处理，「回一条说明」才是。错误是给模型看的信息（能修正的），不是给你看的异常。回一条说明的额外收益：模型会读到它并自己改主意——这就是 agent 自我修正的入口。

症状 → 病因

你看到的现象真正的病因
下一轮请求 400，说 tool_calls 没有对应的 tool 响应 某个 tool_call 被 continue / 条件判断跳过了，没回 tool 消息
程序「卡住」很久，最后打印超过 X 轮 停止判据是白名单（finish_reason === 'stop'），遇到别的取值时空转
日志里只有「达到最大步数」这一行 同上；而且循环体里没有日志，你只能看到结果看不到过程
结果看起来像模像样，但事实上是错的 工具返回了 Infinity / NaN / undefined / [object Object]，模型照单全收或自己圆了过去
程序在工具报错处直接崩掉 JSON.parse 或 tool.execute 抛出的异常没人接
开了 thinking 之后整个会话持续 400 重放历史时手工重建了 assistant 消息，把 reasoning_content 丢了

带 ✓ / ✗ 与 [step N] 的日志不是装饰——agent 的调试几乎全发生在日志里，因为你无法单步跟进一个 HTTP 请求。
